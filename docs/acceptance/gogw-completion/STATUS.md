## 协议边界（已核对已发布 SDK 源码）

已发布 SDK 直接提供：WSS 会话与信封编解码（`api/agent/v1`，`Encode`/`Decode`/`Validate`）、`Register`/`RenewLease`/`UpdateInstance`/`Deregister`、`Subscribe`/`Resume`/`Unsubscribe`、`Snapshot`/`Delta`/`Invalidated`/`ResyncRequired`、`Prepare`/`Activate`/`Abort`/`Revoke`、`DrainRequested`、`ReadinessReport`/`DrainReport`、`ReleaseStatusQuery`、`EventBatch`、签名资源 `Verifier`/`Claims`/`Watermark`、受权 `Download`、带抖动退避的 `Run` 重连。

已发布 SDK **未**定义，必须由本 fork 以版本化扩展补足（并在本文与用户文档中标为扩展，需与真实控制面另行联调）：`RESOURCE_KIND_DISCOVERY`/`RESOURCE_KIND_BUNDLE`/`RESOURCE_KIND_REVOCATION` 资源的 payload 结构、资源 key 派生规则、发现载荷中的 prepared 证据表达、`Prepare.bundle` 的 `ResourceRef` key 约定、下载端点的资源寻址。兄弟仓库工作区（未提交）另有实现，本 fork 不引用其未发布 API，字节级兼容性未经验证。

扩展契约里 `BundleDocument` 有独立的 `policyMaxAgeSeconds`，而 mock 的 `Release` 没有对应字段，只能让 policy 有效期等于 `discoveryMaxAgeSeconds`（`pkg/gogw/mock/release.go`）。因此“两种离线有效期分别到期”的验收不依赖 mock 的该耦合：`TestDiscoveryExpiryStopsServingWithoutPolicyExpiry` 直接发布短 TTL 的成员文档来观察 `DISCOVERY_EXPIRED`，`TestControlOutageAndExpiry` 观察 `POLICY_EXPIRED`。真实控制面可以分别设置这两个值，或省略以取 `pkg/gogw/protocol.go` 的默认值。

## 不能由 gogw 独立解决的外部硬阻塞

1. **真实 Grayling 生产控制面不在本仓库内**，也无法在本环境启动：三个资源 payload 是 fork 自有扩展（`pkg/gogw/protocol.go`，`schema=1`），与真实服务端的字节级互通未验证，也不能验证。
2. **服务端下发 resume token 字段不存在**于已发布信封：断线恢复只能靠快照 + 增量 + watermark 派生 cursor，无法做到服务端断点续传。
3. **证书摘要与 ramp floor / 撤销 epoch 走带外**：前者要求控制面按 `/__gogw/diagnostics` 公布的值写入成员文档，后者是本地持久状态；真实控制面必须按同一合同发布，否则成员会被传输层拒绝或阈值无法被控制面观测。
4. **注册 quorum、审批流程、生产撤销分发、证书签发、真实容量与真实服务端行为**不在 mock 的证明范围内（`docs/content/contributing/gogw.md` 已同样声明）。
