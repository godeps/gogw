// CloseIdleConnections closes any connections which were previously
// connected from previous requests but are now sitting idle in
// a "keep-alive" state. It does not interrupt any connections currently
// in use.
func (t *Transport) CloseIdleConnections() {
	t.nextProtoOnce.Do(t.onceSetNextProtoDefaults)
	t.idleMu.Lock()
	m := t.idleConn
	t.idleConn = nil
	t.closeIdle = true // close newly idle connections
	t.idleLRU = connLRU{}
	t.idleMu.Unlock()
	for _, conns := range m {
		for _, pconn := range conns {
			pconn.close(errCloseIdleConns)
		}
	}
	t.connsPerHostMu.Lock()
	t.dialsInProgress.all(func(w *wantConn) {
		if w.cancelCtx != nil && !w.waiting() {
			w.cancelCtx()
		}
	})
	t.connsPerHostMu.Unlock()

That doc comment predates the branch under it: a dial in progress that has not been
handed to its caller yet is cancelled with the same error, so a request fails even
though the connection was never idle.

Every parallel subtest of Test_Directives defers authServer.Close() on its own
httptest.Server, and the forward-auth middleware dials through the process-global
http.DefaultTransport. Closing any one server therefore closes the shared idle
pool and cancels the dials in progress of the subtests that are still running,
so those subtests answer 500 instead of 200 or 302. Concurrency decides the
outcome; nothing in pkg/gogw is in that process.
